# Local GitHub Repository Code Explainer

A full-stack GenAI application that analyzes public GitHub repositories and generates clear, beginner-friendly explanations dynamically using a **Local LLM via Ollama**, **FastAPI**, and **Streamlit**.

---

## 1. Objective

The objective of this project is to build an automated code explanation tool that helps beginner developers and college students quickly understand unfamiliar open-source projects without relying on paid, closed-source cloud AI APIs.

---

## 2. Problem Statement

Beginner software developers often struggle when exploring open-source repositories on GitHub due to:
- Complex project structures and deeply nested directories.
- Unfamiliar libraries, frameworks, and architecture patterns.
- Lack of clear, beginner-friendly summaries in standard documentation.
- High costs or rate limits associated with cloud GenAI APIs (like OpenAI or Gemini).

This project solves this by running a **100% local, free, open-source Large Language Model (LLM)** on the developer's laptop to parse, summarize, and explain GitHub code repositories.

---

## 3. Architecture

```text
GitHub Repository URL
       ↓
   GitPython (Shallow Clone)
       ↓
Source Code Extraction & Filtering
       ↓
  Code Prioritization & Sizing
       ↓
   Structured Prompt Creation
       ↓
   Ollama HTTP API (localhost:11434)
       ↓
   Local LLM (qwen2.5:3b)
       ↓
 Dynamically Generated Explanation
       ↓
  FastAPI Backend (localhost:8000)
       ↓
 Streamlit Frontend (localhost:8501)
```

---

## 4. Key Features

- **Dynamic Local AI Generation**: Explanations are generated by a local LLM in real-time — never hard-coded.
- **Privacy & Zero Cost**: Operates entirely offline with Ollama; no paid cloud APIs or API keys required.
- **Git Repository Processing**: Clones repositories safely using shallow clones (`depth=1`) and deletes temporary folders immediately after analysis.
- **Smart Source Code Filtering**: Scans supported languages (`.py`, `.js`, `.ts`, `.java`, `.cpp`, `.html`, `.css`, etc.) while strictly ignoring build artifacts, virtual environments (`venv`, `node_modules`), and binary files.
- **Context-Length & Laptop Protection**: Limits file sizes and prioritizes high-value architectural files (`README.md`, `requirements.txt`, `main.py`, `app.py`) to prevent context overflow and reduce CPU load on student laptops.
- **Robust Error Handling**: Handles non-existent repositories, private repositories, network drops, Ollama connection issues, timeouts, and JSON errors gracefully.
- **Simple, Interactive UI**: Clean Streamlit dashboard with real-time status banners, file statistics, language detection, markdown rendering, and an explanation download button.

## 5. Technology Stack

- **Programming Language**: Python 3.10+
- **Local GenAI Runtime**: [Ollama](https://ollama.com/)
- **Local LLM**: `qwen2.5:3b` (Fast, lightweight 3B parameter model suited for consumer laptops)
- **Backend Framework**: FastAPI, Pydantic v2, Uvicorn
- **Repository Processing**: GitPython
- **Frontend Framework**: Streamlit
- **HTTP Client**: Requests

## 7. Installation & Setup (Windows Guide)

### Step 1: Open Terminal in Project Folder
Open PowerShell in the project directory:
```powershell
cd "C:\path\to\github-code-explainers"
```

### Step 2: Create and Activate Virtual Environment
```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

> **Note**: If PowerShell shows an `Execution_Policies` script error, run:
> ```powershell
> Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
> ```
> Then run `.\venv\Scripts\Activate.ps1` again.

### Step 3: Install Required Dependencies
```powershell
pip install -r requirements.txt
```

---

## 8. Ollama Local LLM Setup

### Step 1: Verify Ollama Installation
Make sure Ollama is installed from [ollama.com](https://ollama.com) and running:
```powershell
ollama --version
```

### Step 2: Pull the Recommended Lightweight Model
Download the small, high-performance `qwen2.5:3b` model (approx. 1.9 GB):
```powershell
ollama pull qwen2.5:3b
```

### Step 3: Test Ollama in PowerShell
```powershell
ollama run qwen2.5:3b "Hello, can you explain code?"
```
Once you see a response, type `/bye` to exit the chat.

---

## 9. Running the Application

### Step 1: Start the FastAPI Backend
Open a PowerShell terminal with the virtual environment activated:
```powershell
uvicorn backend.main:app --reload
```
- API Base URL: `http://127.0.0.1:8000`
- Interactive API Docs (Swagger): `http://127.0.0.1:8000/docs`
- Health Endpoint: `http://127.0.0.1:8000/health`

### Step 2: Start the Streamlit Frontend
Open a **second** PowerShell terminal, activate the virtual environment, and run:
```powershell
streamlit run frontend/app.py
```
Streamlit will automatically open in your browser at:
`http://localhost:8501`

---

## 10. Usage Instructions

1. Ensure Ollama is running in the background.
2. In the Streamlit web interface (`http://localhost:8501`), confirm the status badge shows `System Ready`.
3. Paste any public GitHub repository link (e.g., `https://github.com/Bhumikaravi/github-code-explainers`).
4. Click **Explain Repository**.
5. Watch the real-time progress as the repository is cloned, scanned, and explained.
6. Review the summary metrics (files analyzed, languages detected) and the formatted explanation.
7. Click **Download Explanation as Markdown** to save the result.

## 11. Explanation Output Format

The local LLM is instructed to structure its explanation strictly as follows:
- **## Project Overview**: Purpose and high-level goal of the project.
- **## Main Technologies**: Languages, frameworks, and libraries used.
- **## Main Features**: Key functionalities implemented in the code.
- **## How It Works**: Workflow explaining how components interact.
- **## Important Files**: File-by-file breakdown of key modules.
- **## Simple Explanation**: An intuitive analogy or simple breakdown tailored for a beginner student.

## 12. Error Handling & Edge Cases

| Scenario | Handled By | Behavior / Message |
| :--- | :--- | :--- |
| Invalid URL (e.g., `hello`, `https://google.com`) | Regex & URL parser | `Please enter a valid GitHub repository URL.` |
| Repository does not exist (404) | GitPython catch | `Repository not found. Please check the GitHub URL.` |
| Private repository / No access | GitPython catch | `This repository may be private. Please use a public repository...` |
| No supported source code | File scanner | `No supported source-code files were found in this repository.` |
| Corrupt / unreadable file | File reader | Skipped automatically with error logging; continues reading other files. |
| Ollama not started | HTTP connection check | `Ollama is not running. Please start Ollama and try again.` |
| Model not installed | Model tags check | `The required Ollama model is not installed. Please run: ollama pull qwen2.5:3b` |
| LLM takes too long | HTTP timeout handler | `The local LLM took too long to respond. Try analyzing a smaller repository...` |
| Malformed JSON response | Safe type validation | Validates response dictionary types before key access to avoid `TypeError`. |

## 13. Deployment Considerations

### Local Deployment vs. Cloud Deployment

Because this project is built for a college assignment requiring a **Local LLM**, the application is designed to run locally on your personal machine:

- **Local Deployment**:
  ```text
  Your Computer
  ├── Streamlit (Port 8501)
  ├── FastAPI (Port 8000)
  ├── GitPython
  └── Ollama (Port 11434) [Runs on local CPU/GPU]
  ```

- **Why Public Cloud Deployment (e.g., Streamlit Cloud) Cannot Reach Local Ollama**:
  Streamlit Cloud hosts applications in isolated cloud servers on the public Internet. A cloud server cannot access `http://127.0.0.1:11434` on your private Windows laptop behind your home Wi-Fi router.

- **Realistic Options for Public Cloud Deployment**:
  1. **Tunneling (e.g., Ngrok / Cloudflare Tunnel)**: Expose your local Ollama port via an authenticated secure tunnel to the Internet so a cloud frontend can connect to your machine while it is powered on.
  2. **Self-Hosted Cloud VM**: Deploy Ollama, FastAPI, and Streamlit together on a cloud Virtual Machine (e.g., AWS EC2, DigitalOcean Droplet, GCP Compute Engine) with adequate RAM and CPU/GPU.
  3. **Cloud LLM Alternative**: If cloud hosting is ever required without keeping a computer running, an open-source model hosted on Hugging Face Inference Endpoints or an API can be connected. *(Note: For the local assignment requirement, keep running Ollama locally).*
